# CLI 错误诊断

CLI 或 Skill 指令异常时读本文件。Agent 只负责解释原始错误、保留必要诊断事实，并从当前 CLI 支持的能力中选择下一步；外部问题反馈和 CLI 修改由用户自行决定与执行，Skill 不代做。

## 1. 先保留事实

- 保留实际命令、退出码、错误码、错误原文和相关返回 JSON；敏感 token、Cookie 和业务值脱敏。
- 保留本次 session/action/request 标识及对应产物路径，足以说明错误发生在哪一步即可。
- 不要求为每个异常生成固定上报材料；正常验收失败也只需保留测试报告所需证据。
- 原始错误与旧结论不因后续诊断、身份恢复或重试改变。

## 2. 按事实解释

| 现场事实 | 解释与下一步 |
|---|---|
| 命令/参数符合当前 `commands`，实际返回或产物与合同矛盾 | 说明具体合同与差异；从 CLI 支持的只读诊断中补最小事实。证据不足就不确认根因。 |
| Skill/reference 指令与当前 CLI 合同不符 | 指出错误指令、实际合同和可执行替代；不归因 CLI。 |
| 当前 `commands` 缺少所需命令/参数 | 明确能力缺口并报 `BLOCKED`；不拼近似命令，不换其他浏览器工具。 |
| 页面断言失败、业务拒绝或数据缺失 | 按测试报告解释预期与实际；不把业务结果说成 CLI 缺陷。 |
| 登录、权限、网络或浏览器前置失败 | 给出原始错误和当前可用的 CLI 诊断；身份不可恢复时 `BLOCKED`，不自动 fallback。 |
| 参数拼错、过期索引或未按 state 操作 | 说明 Agent 调用错误，按最新合同和页面 state 修正。 |
| 仅有超时或异常码，无法对应生命周期 | 保留缺失事实，不猜根因；结果未知的页面写不重试。 |

错误码不是根因。先对照同一 session/action 的原始返回、页面 state 和实际终态，再给用户能核实的结论。

## 3. 选择 CLI 支持的下一步

- 先按本次实际 `commands GROUP [SUB] --json` 核可用命令和参数，再修正调用。
- 只在本次授权内执行已知无副作用的只读补证；不修改 trace、IR、报告或源码来“修好”证据。
- 超时不证明动作未执行。保存原 session/action/request 和后续 state，不自动重试点击、提交、删除或同一页面写。
- 无法通过 CLI 继续时明确 `BLOCKED` 和缺口；不调用外部平台、不自动升级/切换 CLI、不替用户提问题。
